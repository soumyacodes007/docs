interactive version of this page is in the **API Reference** tab.

## Relayer

### GET /v1/info

```json
{
  "address": "0xfd6c…4725",
  "version": "arkognito-relayer/1",
  "chainId": 7738577,
  "minBatch": 5,
  "maxWaitMs": 60000,
  "minIntervalBlocks": 5,
  "tokensRequired": true,
  "issuer": "0xC3D5…90f1",
  "issuerUrl": "https://relay-1.example.com",
  "maxMinAnonymity": 50,
  "maxHoldMs": 1800000,
  "ohttpKey": "0x…",
  "coverMinBatch": 5
}
```

`issuer` and `issuerUrl` are present when tokens are required; `ohttpKey` when OHTTP is on;
`coverMinBatch` when the relayer pads small batches with cover records. The optional
`semaphoreGroups` array lists accepted group keys. The optional `keeper` flag identifies a
key-keeper service; it does not establish a completed sealed-record client workflow.

### POST /v1/records

Queue a sealed record.

```json
{
  "app": "my-app",
  "owner": "0x0C9E…68C5c",
  "envelope": "{\"v\":1,\"app\":\"my-app\",…}",
  "attributes": {
    "project": { "type": "str", "value": "my-app" },
    "vtag": { "type": "str", "value": "…" },
    "count": { "type": "i32", "value": 3 }
  },
  "expSeconds": 86400,
  "token": { "epoch": 20739, "nonce": "0x…", "signature": "base64…" },
  "minAnonymity": 5,
  "maxHoldMs": 600000
}
```

`u64` and `u256` attribute values are decimal strings. `token` is required when the relayer requires
tokens, except when a configured group proof authorizes the record; `minAnonymity` and `maxHoldMs` are optional. `inbox: true` marks a record written for someone
else, whose envelope is signed by a key other than `owner`.

Returns `202 { "id": "<uuid>" }`.

| Status | When |
| --- | --- |
| `400` | Invalid request: `owner` not an address or equal to the relayer; envelope not padded to 512/1024/4096/16384 bytes; `expSeconds` not a bucket or not equal to the envelope's; `app` mismatch; invalid or uppercase attribute name; missing `project`; more than 32 attributes; `minAnonymity` or `maxHoldMs` out of range; envelope signature does not recover to `owner` (or, with `inbox: true`, does); body not JSON |
| `402` | Tokens required and none sent |
| `403` | Token rejected: invalid, spent, from a day no longer accepted, or no issuer key on Arkiv; required membership missing or group unconfigured |
| `409` | Valid Semaphore nullifier already published or confirmed |
| `413` | Body over 64 KB |
| `429` | Direct attempt limit when tokens are off or a Semaphore gate is configured |
| `503` | Queue full, pending membership reservation, or unavailable membership/history verification |

For a configured Semaphore project, the envelope JSON string includes `membership` with `group`,
decimal `rootBlock` and `proof`. The typed attributes include the five reserved proof projections.
These are inside the existing `envelope` and `attributes`; there is no new top-level proof field
or separate proof-submission endpoint. Missing/unconfigured membership gets `403`, invalid proofs
or bindings get `400`. See [the module reference](/reference/semaphore) and
[entity schema](/reference/entities#semaphore-entities).

### GET /v1/records/:id

```json
{ "id": "…", "state": "queued", "position": 3 }
```

```json
{
  "id": "…",
  "state": "written",
  "entityKey": "0x334c…bb805",
  "txHash": "0x…",
  "block": "352358",
  "batchSize": 5,
  "cover": 4
}
```

```json
{ "id": "…", "state": "failed", "error": "no batch of 5 formed in time; not written" }
```

`position` (queued only) is the number of requests ahead. `404` for an unknown id. Statuses are
kept for an hour after they finish.

<Warning>
  A failed membership status can include a known `txHash`. Reservations remain pending after an
  uncertain outcome; a failed response is not permission to resubmit at another relayer. See
  [reconciliation](/operations/semaphore#restarts-and-uncertain-writes).
</Warning>

### POST /v1/ohttp

An Oblivious HTTP encapsulated request (`message/ohttp-req`, up to 128 KB) carrying any of the
requests above; the response is `message/ohttp-res`. `404` when OHTTP is off, `400` when the request
cannot be opened. See the [protocol reference](/reference/protocol#oblivious-http).

## Token issuer

Served by a relayer started with `ISSUER=on`.

### GET /v1/issuer/key

Query: `app`, `epoch` (today's UTC day number). Publishes today's key on Arkiv if needed:

```json
{ "issuer": "0xC3D5…90f1", "app": "my-app", "epoch": 20739, "entityKey": "0x4097…7efa" }
```

Clients read the key itself from Arkiv, never from this response. `400` if `epoch` is not today.

### POST /v1/tokens/issue

```json
{
  "app": "my-app",
  "epoch": 20739,
  "wallet": "0x2F5d…d31e",
  "blinded": ["base64…", "base64…"],
  "ts": 1791633000000,
  "walletSignature": "0x…",
  "attestation": "KENDRA-9F2C"
}
```

`walletSignature` is the wallet's `personal_sign` of the issuance message (see the
[protocol](/reference/protocol#rate-limit-tokens)). `attestation` only when the issuer requires codes.

```json
{ "blindSignatures": ["base64…", "base64…"], "remaining": 3 }
```

`403` with `{ "error": … }` for: epoch not today, 0 or more than 20 tokens asked for, timestamp more
than 5 minutes off, wrong wallet signature, missing or used attestation code, quota exceeded.

## OHTTP relay

| Endpoint | Description |
| --- | --- |
| `POST /ohttp` | Header `x-arkognito-target: <relayer url>`, body an encapsulated request. Forwarded to `<target>/v1/ohttp`. `403` for unverified targets, `413` over 128 KB, `502` if the relayer fails. |
| `GET /healthz` | `{ "ok": true, "role": "ohttp-relay", "targets": 2 }` |
